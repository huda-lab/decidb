Starting DeciDB…

Step 1

The acts

Maya runs a one-day city festival. Sixteen acts have answered her call, and the table Acts holds what each one asks and brings.

Each row is one act: its genre, its fee in thousands of dollars, the crowd it is expected to draw, and a critics' rating out of 10. Press Run, or Ctrl Enter in the editor. The query runs in this page: DeciDB is compiled to WebAssembly and nothing is sent to a server.

SELECT act, genre, fee, crowd, rating FROM Acts ORDER BY genre, crowd DESC;

The board beside the story draws every act by fee and crowd. It follows each query you run.

Step 2

Book the biggest crowd

Maya has $100k for fees. Which acts draw the largest crowd within it?

In plain SQL this question has no answer: a query can filter and sort the acts, but it cannot search the 65,536 possible lineups. DECIDE adds that search to the query.

SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 100 MAXIMIZE SUM(book * crowd);
DECIDE book(BOOL)
one decision per row: book this act (1) or not (0).
SUCH THAT SUM(book * fee) <= 100
the fees of the booked acts fit the budget.
MAXIMIZE SUM(book * crowd)
of the lineups that fit, return the one with the largest crowd.

DeciDB turns the query into an integer program, solves it with HiGHS, and returns the table with book filled in. Move the budget, press Run, and the lineup changes. At $100k, four of the five acts are electronic: they draw the most people per dollar.

Step 3

Two per genre

A festival of one genre will not do. Maya allows at most two acts of each genre.

SUM(book) by (genre) <= 2 is one constraint for each genre: the sum runs over that genre's rows. It is one more line in the query, and the rest stays as it was.

SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 100 AND SUM(book) by (genre) <= 2 MAXIMIZE SUM(book * crowd);

The lineup now spans all four genres. It draws 1,000 fewer people than the electronic-heavy one: the board's crowd figure is the price of the rule.

Step 4

What if an act cancels?

Plans change. The data changes with them; the query does not.

Each button below changes the Acts table, then runs the query again. DeciDB reads the table each time, so the answer always fits the data as it is now.

SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 100 AND SUM(book) by (genre) <= 2 MAXIMIZE SUM(book * crowd);

Step 5

An impossible request

A sponsor asks for two acts of every genre, and a late bill cuts the budget to $90k.

No lineup meets both, so the query has no answer. DeciDB says so, and does not guess.

SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 90 AND SUM(book) by (genre) >= 2 MAXIMIZE SUM(book * crowd);

Put DIAGNOSE in front of the same query and DeciDB names the smallest change that gives it an answer. Press Apply on a suggestion to make that change in the query above and run it.

DIAGNOSE SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 90 AND SUM(book) by (genre) >= 2 MAXIMIZE SUM(book * crowd);

Step 6

No solver needed

Maya's last plan ignores the fees: one or two acts of each genre, the best rated.

Acts rated above 8 add to the objective and acts below 8 take from it, so each genre books its best act, and its second best only if that act is rated above 8. DeciDB recognizes this shape (rule S1: the best rows of each group) and rewrites the query into sorting and ranking. No solver starts.

SELECT act, genre, rating, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book) by (genre) >= 1 AND SUM(book) by (genre) <= 2 MAXIMIZE SUM((rating - 8) * book) ORDER BY genre, rating DESC;

How much faster?

Make a table of many acts and run the same query twice: once as DeciDB runs it, and once with decide_direct_solve = 'off', which sends it to the solver. Both return the same lineup.

SELECT genre, COUNT(*) AS booked FROM (SELECT act, genre, book FROM Big DECIDE book(BOOL) SUCH THAT SUM(book) by (genre) >= 1 AND SUM(book) by (genre) <= 2 MAXIMIZE SUM((rating - 8) * book)) WHERE book = 1 GROUP BY genre ORDER BY genre;
Acts in Big

The solver here is HiGHS compiled to WebAssembly, on one thread. On your own machine DeciDB uses every core, and Gurobi when it finds a license, so both paths run faster there. The performance page has the native timings.

Step 7

Your turn

Write your own query. Acts and Big are loaded; any SQL works.

Try SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * crowd) >= 30000 MINIMIZE SUM(book * fee); SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book) by (genre) = 1 AND SUM(book * fee) <= 80 MAXIMIZE SUM(book * crowd); SELECT act, genre, fee, rating, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 60 MAXIMIZE SUM(book * rating); EXPLAIN SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 100 AND SUM(book) by (genre) <= 2 MAXIMIZE SUM(book * crowd);
SELECT act, genre, fee, crowd, book FROM Acts DECIDE book(BOOL) SUCH THAT SUM(book * fee) <= 120 AND SUM(book) by (genre) BETWEEN 1 AND 2 MAXIMIZE SUM(book * crowd);

The guide explains every clause, and the examples have 20 problems to copy from. To run DeciDB on your own data, install it: the same queries run there on every core, with your files and databases.
