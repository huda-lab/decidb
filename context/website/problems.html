Problems you can express

You never name the problem class. DeciDB reads it from the decision types and the shape of each term, picks a formulation, and either answers the query directly or hands it to a solver that can take it.

Modeling patterns #

The shapes below cover most decision problems over tables. Each links to a complete example with data and the answer DeciDB returns.

Selection under a budget

Pick rows; a weighted sum stays within a limit.

DECIDE x(BOOL) SUCH THAT SUM(x * weight) <= 50 MAXIMIZE SUM(x * value)

Quantities and capacities

Decide an amount per row, bounded per row, meeting a total.

DECIDE units(INT) SUCH THAT units <= capacity AND SUM(units) >= 500

Assignment and matching

Every task gets one person, nobody gets two.

per worker: SUM(a) by (worker) <= 1 per task: SUM(a) by (task) = 1

Limits per group

One constraint for every group in the data, with no list of groups in the query.

per sector: SUM(pick) by (sector) <= 2

Fixed cost plus variable cost

Open a facility before using it; pay its fixed cost once.

DECIDE per D: open(BOOL), ship(INT) ... SUM(ship) by (D) <= D.capacity * open MINIMIZE ... + SUM(D: D.opening_cost * open)

Worst case (min-max)

One shared decision bounds every group; minimize it.

DECIDE ship(INT), per (): worst(INT) ... per g: g.demand - SUM(ship) by (g) <= worst MINIMIZE worst

Load balancing

The two-level objective: a max over groups of a sum within each.

MINIMIZE max(per m: SUM(run * hours) by (m))

Fairness (max-min)

Raise the worst-off row as far as the budget allows.

MAXIMIZE MIN(alloc / need)

Sparse and robust changes

Count changes with L0, bound the largest with L∞, total them with L1.

norm(new - old, 0) <= 2 MINIMIZE norm(new - old, 'inf')

Closest to a target

Least squares over a feasible region: a convex QP.

MINIMIZE SUM(POWER(w - target, 2))

Feasibility

No objective: any assignment that satisfies the rules.

SUCH THAT per shift: SUM(on) by (shift) = 1

Explaining infeasibility

Which clause to change, and by how much.

DIAGNOSE SELECT ... DECIDE ...

Problem classes and solvers #

DeciDB uses Gurobi when its library and a license are present, and the bundled HiGHS otherwise. A model that the available solver cannot take is refused at plan time, before reading a row, with a message that names what the query does and which solver it needs. The same SQL runs on a machine with Gurobi.

Answered without a solver #

Nine problem classes have an exact answer that DuckDB's own operators compute. When DeciDB proves a query belongs to one, it replaces the solve with sorting, ranking, window and aggregate operators. The query is unchanged; EXPLAIN names the rule.

Faster and exact

Every class is faster than Gurobi at every size measured, by up to several orders of magnitude once the input reaches hundreds of thousands of decisions. The answer is exact, without the solver's tolerance, and a quadratic class needs no Gurobi license. SET decide_direct_solve = 'off' sends every query to the solver.

The R1 answer fills the truck with the most valuable goods per kilogram first. The A1 answer puts each quantity at whichever end of its range its margin favors. N1 points x along the scores, scaled to the limit: with scores 3, 4 and 0 and a limit of 25, it answers 3, 4 and 0.

What DeciDB adds for you #

Several shapes are not linear as written. DeciDB rewrites them into a form the solver takes, and EXPLAIN shows each rewrite under the clause it came from.

You writeDeciDB adds
ABS(e) in a constraint or objectivean auxiliary variable and two rows; a binary when the direction needs one
the hard direction of MIN/MAXan extremum variable per group, tied by indicator rows (native on Gurobi)
<>one binary and two rows, or a single inequality when one side is out of reach
x IN (a, b, c)one binary per value
norm(e, 0)one indicator per row, pinned both ways
b * x with b a BOOLa McCormick envelope: exact, no Big-M on the binary side
a reducer inside another expression, or beside a row-varying terma helper decision per group, defined once and shared by every clause that reads it
SQLRuns as shown
SELECT item, x
FROM Items
DECIDE x(INT)
SUCH THAT x <= 3
      AND ABS(SUM(x * weight) - 60) <= 10
      AND SUM(x) <> 4
MAXIMIZE SUM(x * value);
EXPLAIN: the DECIDE node
DECIDE
  Variables: x
  Objective: ['MAXIMIZE SUM(x * value)', '  ≡ sum(value * x)']
  Constraints:
    x <= 3
    ABS(SUM(x * weight) - 60) <= 10
      ≡ abs(sum(weight * x) - 60) <= 10
      ↳ abs(sum(weight * x) - 60) becomes an auxiliary variable
      ↳ sum(weight * x) becomes a helper decision
      ↳ abs(sum(weight * x) - 60) - sum(weight * x) >= -60
      ↳ abs(sum(weight * x) - 60) + sum(weight * x) >= 0 + 60
    SUM(x) <> 4
      ↳ sum(x) <> 4 becomes two conditional rows with an indicator
