Install

Three ways in: the command-line shell, the Python package, or a build from source.

Command-line shell

The command-line shell is one self-contained binary. Download the archive for your platform:

PlatformRequirements
Linux x86-64Ubuntu 18.04+, CentOS 7+Download
macOS (universal)macOS 11+Download
Windows x64Windows 10+Download
Linux / macOS
unzip decidb_cli-osx-universal.zip     # or the Linux archive
chmod +x decidb
./decidb --version
Windows (PowerShell)
Expand-Archive decidb_cli-windows-amd64.zip -DestinationPath .
.\decidb.exe --version
Unsigned binaries

On macOS, right-click the binary, choose Open and confirm. On Windows, choose "More info" and then "Run anyway" in SmartScreen.

Release 0.2 and this site

The current release, 0.2, uses the earlier spellings, such as PER after a constraint. The queries on this site use the new ones; the guide's migration table lists each change.

Python

Wheels are published for Python 3.11, 3.12 and 3.13 on macOS (Apple Silicon), Linux (x86-64) and Windows (x86-64). The API is DuckDB's.

Shell
pip install decidb
Python
import decidb
decidb.connect().sql("SELECT 42").fetchall()

Build from source

You need a C++17 compiler, CMake 3.15+, Python 3 and Git; Ninja is used when present.

Shell
git clone https://github.com/huda-lab/decidb.git
cd decidb
make release
./build/release/decidb --version

On Windows, with Visual Studio 2019+ and Ninja:

Windows (PowerShell)
cmake -G Ninja -B build/release -DCMAKE_BUILD_TYPE=Release -DDISABLE_UNITY=1
ninja -C build/release

Your first query

Start the shell. With no file name the database lives in memory; ./decidb shop.db opens or creates a file.

Shell
./decidb

Create a small table of items, each with a value and a weight:

SQLRuns as shown
CREATE TABLE Items (item VARCHAR, value INT, weight INT, category VARCHAR);
INSERT INTO Items VALUES
    ('Laptop', 100, 20, 'tech'), ('Camera', 60, 10, 'tech'), ('Drone', 120, 30, 'tech'),
    ('Tripod', 40, 15, 'gear'), ('Lens', 75, 12, 'gear');

Which items should go in a bag that holds 50 kg, to carry the most value?

SQLRuns as shown
SELECT item, value, weight, x AS take
FROM Items
DECIDE x(BOOL)
SUCH THAT SUM(x * weight) <= 50
MAXIMIZE SUM(x * value);
Result5 rows
itemvalueweighttake
Laptop100201
Camera60101
Drone120300
Tripod40150
Lens75121

The query returns every row, with the decision x filled in: 1 for the laptop, camera and lens, 0 for the rest. Together they weigh 42 kg and are worth 235, and no other choice under 50 kg is worth more.

Anatomy of a DECIDE query

A DECIDE query is a SELECT with three more clauses. In the query above:

DECIDE x(BOOL)
declares the decisions: here one yes-or-no value x per row. Every decision has a name and a type in parentheses.
SUCH THAT SUM(x * weight) <= 50
states the constraints, joined by AND. A constraint with a sum holds over many rows; one without, such as x <= cap, holds on every row.
MAXIMIZE SUM(x * value)
states the objective. Write MINIMIZE for a cost, or leave it out to ask for any answer that satisfies the constraints.
SELECT, FROM, WHERE
are ordinary SQL. FROM and WHERE run first and pick the rows that get decisions; SELECT and ORDER BY run after the solve and read the decisions like columns.

The declaration can also sit between SELECT and FROM, the order the DeciDB paper uses. Both orders mean the same:

SQLRuns as shown
SELECT item, x
DECIDE x(BOOL)
FROM Items
SUCH THAT SUM(x * weight) <= 50
MAXIMIZE SUM(x * value);

Decisions

TypeValuesReturned asUse it for
BOOL0 or 1INTEGERpick or skip, open or closed
INT0, 1, 2, … by defaultBIGINTwhole quantities
REAL0 or more by defaultDOUBLEamounts, shares, positions

Zero is a default lower bound, not a floor: a constraint such as x >= -10 or x BETWEEN -5 AND 5 lets an INT or REAL decision go negative.

A decision can also be shared. per K: in front of a declaration makes one decision per distinct value of K, and per (): makes exactly one for the whole query. Over shipments joined to the depots they leave from:

SQLRuns as shown
SELECT S.shipmentID, D.depotID, ship, open, biggest
FROM Shipment S JOIN Depot D USING (depotID)
DECIDE ship(INT), per D: open(BOOL), per (): biggest(INT)
SUCH THAT ship <= S.demand * open
      AND ship <= biggest
      AND SUM(ship) >= 150
MINIMIZE SUM(S.unit_cost * ship) + SUM(D: D.opening_cost * open) + 10 * biggest;

ship is one decision per shipment row, open one per depot, shared by that depot's shipments, and biggest one for the whole query: the largest single shipment, which the objective keeps small. More on decisions.

Rules about groups

Constraints often apply group by group. Three keywords, written in front of a constraint or after a reducer, say which rows a rule covers:

WriteMeaning
when category = 'A': SUM(x) >= 2Look only at the rows where the condition holds.
per sector: SUM(x) by (sector) <= 2One constraint per sector; each sum reads its own sector's rows.
SUM(when morning: x * hours) <= 20A condition on one sum only.
x <= 0.25 * SUM(x) by (region)Each row at most a quarter of its region's total.

From Python

The decidb package has DuckDB's API, so a DECIDE query runs like any other and returns a relation you can turn into a DataFrame:

Python
import decidb

con = decidb.connect()
con.sql("CREATE TABLE Items AS SELECT * FROM 'items.csv'")
answer = con.sql("""
    SELECT item, x FROM Items
    DECIDE x(BOOL)
    SUCH THAT SUM(x * weight) <= 50
    MAXIMIZE SUM(x * value)
""").df()

Solvers

DeciDB carries the bundled HiGHS solver and needs nothing else for linear, integer and convex quadratic models. When the Gurobi library and a license are present, DeciDB uses Gurobi: it is faster on these workloads and also takes non-convex and mixed-integer quadratic models and quadratic constraints. A model that only Gurobi can solve is refused, with a message, when Gurobi is not available. Some problems need neither: query rewriting answers them with DuckDB's own operators. The guide lists which solver takes which kind of query.
