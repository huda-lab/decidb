Write the model in SQL. Decisions, rules and the goal sit in one DECIDE query.

Declares one decision per key

per n: keep(BOOL) gives each nurse one decision, shared by every shift row the join returns.

DECIDE per n: keep(BOOL)
SUCH THAT SUM(keep * s.hours) <= 60
MAXIMIZE SUM(per n: keep * n.skill_score)

when picks the rows a constraint reads. Here the bag takes at most one tech item.

Refuses a constraint the data cannot decide

A depot ships several rows, so a cap per depot on a decision per row stops before solving.

DECIDE ship(INT)
SUCH THAT ... AND per D.depotID: ship <= 10
Error DECIDE: per D.depotID does not determine the decision ship (declared per row). D.depotID = 'D1' covers more than one ship.

The query is the model

Three clauses added to a SELECT. The rows stay in DuckDB from the scan to the answer.

DECIDE x(BOOL)

The decisions: one per row, per key or per query.

SUCH THAT ...

The constraints, on each row or on sums over groups.

MAXIMIZE ...

The goal; leave it out to ask for any answer that fits.

Built on DuckDB, solved by Gurobi or HiGHS

DeciDB is DuckDB with the DECIDE clause added, so it reads the same tables and files. HiGHS ships in every build; Gurobi is used when its license is present.

  • Python: pip install decidb, with DuckDB's API
  • A command-line shell for macOS, Linux and Windows
  • LP, MILP and convex QP on HiGHS; non-convex QP, MIQP and QCQP need Gurobi

Questions

On solvers, releases and what happens when a model has no answer.

Ask on GitHub

Do I need a Gurobi license?

No. HiGHS is bundled and solves LP, MILP and convex QP. With a Gurobi license, DeciDB also takes non-convex and mixed-integer quadratic models.

Does ordinary DuckDB SQL still work?

Yes. DeciDB is DuckDB with one more clause; a query without DECIDE runs as it does in DuckDB.

What happens when no answer meets every constraint?

The query stops and says so. Put DIAGNOSE in front of it to see which clause to change and by how much.

Can I see the optimization model it builds?

Yes. EXPLAIN shows the DECIDE node with its variables, constraints and objective, and the direct-solve rule when one applies.

Does release 0.2 run the queries on this site?

No. Release 0.2 uses the earlier spellings, such as a postfix PER. The guide's migration table lists each change.
