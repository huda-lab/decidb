Why optimization belongs in the database

Without DeciDB

Read the rows out, rebuild the problem in a solver library, solve it, and load the answer back in.

import duckdb, pulp

rows = duckdb.sql("SELECT * FROM Items").fetchall()

bag = pulp.LpProblem("bag", pulp.LpMaximize)
take = {i: pulp.LpVariable(i, cat="Binary") for i, _, _ in rows}
bag += pulp.lpSum(v * take[i] for i, v, _ in rows)
bag += pulp.lpSum(w * take[i] for i, _, w in rows) <= 50
bag.solve()

answer = [(i, round(take[i].value())) for i, _, _ in rows]
duckdb.sql("CREATE TABLE Answer (item VARCHAR, take INT)")
duckdb.executemany("INSERT INTO Answer VALUES (?, ?)", answer)

With DeciDB

One query over the table. The answer comes back as rows, ready to join with the rest of your data.

SELECT item, value, weight, x AS take
FROM Items
DECIDE x(BOOL)
SUCH THAT SUM(x * weight) <= 50
MAXIMIZE SUM(x * value);

The query is the model

Three clauses added to a SELECT. The rows stay in DuckDB from the scan to the answer.

DECIDE x(BOOL)

The decisions: what DeciDB chooses, one per row, per key or per query.

SUCH THAT ...

The constraints: the rules every answer follows, on each row or on totals.

MAXIMIZE ...

The objective: what makes an answer best. Leave it out to ask for any answer that fits.

Novel features. Two things a solver library does not do.

Query rewriting

A query with an exact answer, such as a fair split of a budget, runs as sorting and aggregation in DuckDB, with no solver: 0.026 s at 800,000 decisions, where Gurobi took 2,158 s.

SELECT program, alloc
FROM Programs
DECIDE alloc(REAL)
SUCH THAT alloc <= max_alloc
  AND SUM(alloc) <= 100
MAXIMIZE MIN(alloc / need);
EXPLAINDirect solve rule: R4_MAX_MIN_FAIRNESS

DIAGNOSE for a query with no answer

Put it in front of the query and it returns the clause to change and by how much: here, a weight limit of 57 instead of 40.

DIAGNOSE
SELECT item, x FROM Items
DECIDE x(BOOL)
SUCH THAT SUM(x * weight) <= 40
  AND SUM(x) >= 4

Built on DuckDB, solved by Gurobi or HiGHS

DeciDB is DuckDB with the DECIDE clause added, so it reads the same tables and files. HiGHS ships in every build; Gurobi is used when its license is present.

  • The data never leaves DuckDB: the model is built from the query's own rows
  • Python: pip install decidb, with DuckDB's API
  • A command-line shell for macOS, Linux and Windows
  • You state the rules and the goal; DeciDB writes the model the solver reads
