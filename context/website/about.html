The idea

WHERE filters one row at a time. DECIDE constrains the whole set of decisions at once.

Package queries asked a database for a set of rows that satisfies constraints over the set: a meal plan under a calorie budget, a portfolio within a risk limit. DeciDB generalizes them from choosing rows to deciding values of any type (yes or no, whole quantities, continuous amounts), shared per row, per key or for the whole query, and from linear rules to quadratic and bilinear ones.

The DECIDE language follows the language proposal developed with the project: three scope words (per, when, by) that each answer one question about a rule, and a determination rule that keeps every constraint well defined on the data it runs on.

How it is built

DuckDB
The embeddable analytical engine DeciDB extends: parser, binder, optimizer and execution each own one part of a DECIDE query.
Gurobi
Used when its library and license are present: every model class, and the fastest on these workloads.
HiGHS
Bundled and open source: LP, MILP and convex QP, with no setup.
Query rewriting
Rules that recognize nine problem classes with an exact relational answer and rewrite the query to compute it with DuckDB operators, skipping the solver.
Testing
More than 7,000 Python cases, each comparing DeciDB's answer with an independent Gurobi model, run with each solver and with query rewriting on and off.
Distribution
Tagged releases ship command-line binaries for macOS, Linux and Windows, and Python wheels.

What comes next

  • The rest of the language proposal: nested reducers at any depth, frame selectors for ordered data, if on decisions, declaration bounds and lexicographic objectives (details).
  • More query-rewriting classes: the catalogue lists further classes with exact relational answers, such as discrete resource allocation and transportation on sorted costs.
  • Sketch-Refine: scale past exact solving to very large inputs with a bounded approximation error.
