A shortlist: the best two per genre

Pick at most two films per genre with the highest total rating. DeciDB ranks rows instead of calling a solver.

Query rewritingILP
decidb · shortlist.sql
SELECT title, genre, rating, pick
FROM Films
DECIDE pick(BOOL)
SUCH THAT per genre: SUM(pick) by (genre) <= 2
MAXIMIZE SUM(rating * pick)
ORDER BY genre, rating DESC;

The problem

Choosing rows by score under a count limit has an exact answer: sort by score and take the top k in each group. DeciDB proves the query has that shape and computes it with window operators.

Answered by query rewriting: DeciDB computes the optimum with sorting and joins, and no solver is called. EXPLAIN names the rule, S1_UNIFORM_MATROID.

How it reads

per genre: SUM(pick) by (genre) <= 2
A count limit per group.
MAXIMIZE SUM(rating * pick)
A linear score: the class DeciDB calls S1, choose rows by score.

The answer

The two highest-rated films of each genre. EXPLAIN on this query shows Direct solve rule: S1_UNIFORM_MATROID: the query was rewritten, and no solver was started.
