A shortlist: the best two per genre

Pick at most two films per genre with the highest total rating. DeciDB ranks rows instead of calling a solver.

Direct solve S1ILP

The problem

Choosing rows by score under a count limit has an exact answer: sort by score and take the top k in each group. DeciDB proves the query has that shape and computes it with DuckDB's own window operators.

The data

SetupRuns as shown
CREATE TABLE Films (title VARCHAR, genre VARCHAR, rating DOUBLE);
INSERT INTO Films VALUES
    ('Northern Lights', 'Drama', 8.6), ('Paper Boats', 'Drama', 7.9),
    ('The Long Field', 'Drama', 8.1), ('Quiet Harbor', 'Drama', 7.2),
    ('Laugh Track', 'Comedy', 7.4), ('Second Helping', 'Comedy', 8.0),
    ('Odd Couples', 'Comedy', 6.9), ('Deep Orbit', 'Sci-fi', 8.8),
    ('Red Dust', 'Sci-fi', 7.7), ('Signal', 'Sci-fi', 8.3);

The query

DECIDE queryRuns as shown
SELECT title, genre, rating, pick
FROM Films
DECIDE pick(BOOL)
SUCH THAT per genre: SUM(pick) by (genre) <= 2
MAXIMIZE SUM(rating * pick)
ORDER BY genre, rating DESC;

How it reads

per genre: SUM(pick) by (genre) <= 2
A count limit per group.
MAXIMIZE SUM(rating * pick)
A linear score: the class DeciDB calls S1, choose rows by score.

The answer

The two highest-rated films of each genre. EXPLAIN on this query shows Direct solve rule: S1_UNIFORM_MATROID; the solver is never started.
