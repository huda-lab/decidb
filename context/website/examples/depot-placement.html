Place one depot per highway

Choose a mile marker for one depot on each highway that minimizes the total distance to that highway's stores.

Query rewritingLP
decidb · depot-placement.sql
SELECT highway, store, mile, depot
FROM Stores
DECIDE per highway: depot(REAL)
SUCH THAT depot <= 100
MINIMIZE SUM(ABS(depot - mile));

The problem

One shared value closest to many rows is a median (for absolute distance), a mean (for squared distance) or a midrange (for the largest distance). A keyed decision makes one such value per highway.

The data

SetupRuns as shown
CREATE TABLE Stores (store VARCHAR, highway VARCHAR, mile DOUBLE);
INSERT INTO Stores VALUES
    ('S1', 'I-10', 3), ('S2', 'I-10', 8), ('S3', 'I-10', 9), ('S4', 'I-10', 20),
    ('S5', 'I-95', 2), ('S6', 'I-95', 6), ('S7', 'I-95', 40);

Answered by query rewriting: DuckDB's own operators compute the optimum and no solver is called. EXPLAIN names the rule, A2_SINGLE_FACILITY_LOCATION.

How it reads

DECIDE per highway: depot(REAL)
One depot position per highway, shared by that highway's rows.
SUM(ABS(depot - mile))
Total distance to the stores. ABS over a decision is allowed.

The answer

A median per highway: mile 6 on I-95. On I-10, with four stores, any point from mile 8 to mile 9 is optimal and DeciDB returns 8. The I-95 store at mile 40 does not pull the depot toward it, as it would with squared distance.
