Fit as many tickets as possible into a sprint

With 20 story points of capacity, take the largest number of tickets.

Direct solve S3ILP

The problem

When every item is worth the same, a knapsack has an exact greedy answer: take the smallest items first. DeciDB recognizes the shape (a count objective and one weight budget) and sorts instead of searching.

The data

SetupRuns as shown
CREATE TABLE Backlog (ticket VARCHAR, points INT);
INSERT INTO Backlog VALUES
    ('API-12', 5), ('API-15', 3), ('UI-4', 2), ('UI-9', 8),
    ('DB-2', 1), ('DB-7', 5), ('OPS-3', 3), ('OPS-8', 13);

The query

DECIDE queryRuns as shown
SELECT ticket, points, take
FROM Backlog
DECIDE take(BOOL)
SUCH THAT SUM(points * take) <= 20
MAXIMIZE SUM(take)
ORDER BY points;

Answered by direct solve (S3_MAX_CARDINALITY_KNAPSACK): DuckDB operators compute the optimum, no solver is called.

How it reads

SUM(points * take) <= 20
One budget.
MAXIMIZE SUM(take)
Count the tickets: every ticket is worth one.

The answer

Six tickets for 19 points. The eight-point ticket would fit only by dropping two smaller ones.
