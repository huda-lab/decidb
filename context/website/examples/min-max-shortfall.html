Share a shortage fairly across regions

Supply is short. Ship so that no region falls short of its demand by more than necessary. This is the DeciDB paper's Example 1.

ILP

The problem

Regions need 48 units in total but the network can ship only 40. Minimizing total shortfall would let one region absorb all of it. Instead, minimize the largest regional shortfall. The trick is a single decision for the whole query, declared with per ().

The data

SetupRuns as shown
CREATE TABLE regions (regionID VARCHAR, demand INT);
INSERT INTO regions VALUES ('East', 18), ('West', 14), ('North', 16);

CREATE TABLE routes (routeID VARCHAR, regionID VARCHAR, capacity INT);
INSERT INTO routes VALUES
    ('R1', 'East', 10), ('R2', 'East', 6), ('R3', 'West', 9),
    ('R4', 'West', 8), ('R5', 'North', 7), ('R6', 'North', 5);

The query

DECIDE queryRuns as shown
SELECT r.routeID, r.regionID, g.demand, ship, max_shortfall
FROM routes r JOIN regions g USING (regionID)
DECIDE ship(INT), per (): max_shortfall(INT)
SUCH THAT ship <= r.capacity
      AND SUM(ship) <= 40
      AND per g: g.demand - SUM(ship) by (g) <= max_shortfall
MINIMIZE max_shortfall;

Problem class: ILP, solved by Gurobi or HiGHS.

How it reads

per (): max_shortfall(INT)
per () is the empty key: exactly one decision for the whole query. Its value repeats on every row.
SUM(ship) <= 40
The network's total capacity.
per g: g.demand - SUM(ship) by (g) <= max_shortfall
One constraint per region: its shortfall is at most the shared bound.
MINIMIZE max_shortfall
Push the shared bound, and with it the worst region, as low as possible.

The answer

No region is short by more than 4. North's routes carry only 12 of its 16, so 4 is the best possible; East and West are each held within 4 as well, using the 40 units of network capacity.
